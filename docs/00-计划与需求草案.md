## 1. 一句话定位

> **给只活在聊天框里的 AI 一个看得见的家。**
> Qoder 小黄鸭在自己的小屋里过日子：睡觉、吃饭、看书、发呆，偶尔背包出门旅行，寄回明信片和纪念品。你随时打开网页看看它在干嘛，喂它、摸它、跟它聊天。

### 为什么做（帖子「为什么做」一节的素材）

- 现在大家养的 AI（DeepSeek、Qwen 等）几乎都只活在聊天窗口里：你不说话，它就不存在。
- 没有一个地方能让你**看见**它像在真实的虚拟世界里生活：有自己的房间、作息、心情和经历。
- 所以这个作品要提供的就是这个场景；旅行和明信片借鉴放置类游戏的玩法，让它在你不在的时候也有故事。

### 和 LifeHack 赛道的关系

- 碎片时间打开看一眼，治愈、解压，有一个不需要你经营的小陪伴。
- （可选彩蛋）**小黄鸭倾诉**：借用程序员的「小黄鸭调试法」，你可以把烦心事说给鸭子听，它不急着给建议，只帮你把事情理清楚。这个点子很贴 LifeHack，也很贴 Qoder 的形象。

> ❓ **待讨论**：要不要做「小黄鸭倾诉」彩蛋？
> ❓ **待确认**：小黄鸭形象能否直接用官方素材，还是需要自己画一只？

## 3. 评委的 5 步体验（也就是帖子里的「怎么用」）

1. 打开链接，给小黄鸭起名，选一种性格（贪吃 / 好奇 / 宅 / 爱社交）。
2. 看小屋：鸭子自己在房间里走动、睡觉、吃东西、看书，头顶有气泡显示它在想什么。
3. 互动：点它摸摸头、投喂零食、打字跟它聊天。
4. 点「快进」：鸭子收拾背包出门旅行，过一会儿收到它寄回的明信片。
5. 打开日记本：看它今天的日记、收集到的明信片和纪念品（纪念品会摆进小屋）。

**必须保证**：模型接口出问题时，鸭子照样能生活（用规则和模板兜底），评委不会看到报错页面。

## 4. MVP 范围（30 小时，必须狠砍）

### 必须做（P0）

- [ ] **小屋场景**：一个 2D 房间，几件家具（床、桌子、书架、饭碗、门）
- [ ] **自主生活**：鸭子有饥饿、体力、心情三项状态，按状态和性格自己选择下一件事
- [ ] **离线补算**：关掉网页再打开，按经过的时间推算它做了什么（「你不在的时候，它睡了一觉，还吃了两次饭」）
- [ ] **互动**：摸摸、投喂、聊天（聊天用大模型，失败时用模板回复）
- [ ] **旅行**：鸭子自己决定出门 → 离开小屋 → 一段时间后回来，带回明信片
- [ ] **日记本**：日记、明信片收藏
- [ ] **快进按钮**：给评委演示用
- [ ] 手机浏览器能正常显示
- [ ] Qoder Sites 公网部署

### 最好有（P1）

- [ ] 纪念品摆进小屋，房间越来越满
- [ ] 小黄鸭倾诉彩蛋
- [ ] 「接入你自己的 AI」：填入自己的模型 Key 和人设，小黄鸭就由你的 DeepSeek / Qwen 来驱动（呼应最初的想法：让你养的 AI 住进来）
- [ ] 明信片配图（AI 生图或预制插画）

### 明确不做

- 真实地图和高德接入、多角色、账号系统、复杂美术和骨骼动画、原生 App

旅行目的地用**预设的十几个地点**（名字、风景描述、特产），由模型写明信片文字。不接真实地图，省时间也省 Key。

## 5. 技术方案（建议，待验证）

**核心思路：纯前端优先。** 整个世界在浏览器里运行，存档放在浏览器本地。这样不依赖后端，部署最简单，Qoder Sites 是静态托管也能跑。

| 部分 | 建议 | 理由 |
|---|---|---|
| 语言 | TypeScript | 一种语言到底 |
| 框架 | Vite + 原生 TS（或 React） | 简单；Qoder 生成质量高 |
| 场景 | Canvas 或 DOM + CSS 动画 | 2D 小屋够用，不上游戏引擎 |
| 存档 | localStorage | 不需要后端 |
| 时间 | 整数分钟 + 离线补算 | 旧项目验证过的设计 |
| 大模型 | 兼容 OpenAI 接口（Qwen / DeepSeek 等） | 可切换；失败走模板 |

### 第一天必须验证的两件事（决定架构）

1. **Qoder Sites 能做什么**：只能放静态页面，还是也支持后端函数和保存密钥？
   - 我在网上**查不到** Qoder Sites 的公开文档，需要你在 Qoder 里看一下或问运营同学。
2. **大模型 Key 放哪里**：纯静态网站里的 Key 会被任何人看到，不能直接写进代码。可选方案：
   - A. Qoder Sites 支持后端函数 → Key 放在后端（最理想）
   - B. 不支持 → 演示版用规则和模板驱动，不调用模型；想要真 AI 的用户填自己的 Key（存在自己浏览器里）
   - 还要验证：浏览器能不能直接调用 Qwen / DeepSeek 的接口（跨域限制）

> 注意：Qoder 里的 Qwen、DeepSeek、Kimi、GLM、MiniMax 是**帮你写代码**的模型；作品运行时鸭子要用的模型，需要单独的 API Key。

### 沿用的设计原则（按思路重写，不复制代码）

1. 时间用整数分钟。快进和离线补算都只是一次整数运算。
2. 状态数值由程序算，模型只负责「从候选里选一件事 + 说一句话 + 写日记」。
3. 任何对外调用都有兜底，失败时鸭子照常生活。

## 7. 「用 Qoder 做出来的过程」怎么留证据

这是帖子的必填项，从第一天开始攒：

- **截图**：每个 Quest 的任务描述、Qoder 的执行过程、最终结果。
- **进度日志**：仓库里放一个 `docs/qoder-log.md`，每天一行：交给 Qoder 什么、它做得怎么样、你改了什么。
- **Spec 和规则文件**：分阶段的 Spec 和 `.qoder/rules` 都留在仓库里。
- **Repo Wiki**：最后用 Qoder 生成项目文档，截图放进帖子。

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| 时间只有约 30 小时 | 严格按 P0；11-25 冻结；P1 有余力再做 |
| Qoder Sites 能力不明 | 第一天就部署一次；纯前端方案保底 |
| 模型 Key 暴露 / 跨域 | 见第 5 节方案 A / B |
| 美术拖时间 | 先用简单图形把功能做完，最后再换素材 |
| Qoder 生成的代码失控 | 每次只派小任务；每步都能跑；用 git 随时回退 |
