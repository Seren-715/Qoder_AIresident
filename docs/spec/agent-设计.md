# 小黄鸭 Agent 设计

> 11-14。记录已经定下的方向，供后续各阶段的 Spec 引用。这里只写结构和规矩，不写实现细节。

---

## 1. 一句话

**身体归程序，心归模型，记忆把两者连起来。** 鸭子本身就是一个小 Qoder：任务公告板是 Quest，记忆墙是 Memory，书架是 Wiki，门边的家规木牌是 Rules。

## 2. 五层

| 层 | 谁负责 | 做什么 | 阶段 |
|---|---|---|---|
| 身体 | 程序 | 时间、饱腹、体力、心情、当前活动；写下事件流 | 一 |
| 快脑 | 程序（规则） | 每件事做完后选下一件；离线补算也靠它 | 一 |
| 嘴 | 模型 | 带上下文的聊天、当天日记、明信片上的话 | 二 |
| 记忆 | 两者 | 事件流、日记、关于你的卡片、导入的记忆 | 二 |
| 慢脑 | 模型 | 一天几次的大决定：要不要出门、去哪、怎么回应你的愿望 | 三 |

两条规矩：

1. **模型只能从程序给的候选里选**，输出「选项 + 理由 + 一句话」。数值、时间、地点它改不了；格式不对就重试一次，再不行用规则兜底。
2. **鸭子说的不算事实，事件流才算。** 聊天时只让它引用事件流、日记和记忆卡片里有的东西。

## 3. 人设

- **默认人设固定：Qoder 的编程小鸭。** 圆滚滚、眉毛看着不太服气但心很软；喜欢写代码和看书；懂一点「小黄鸭调试法」，你把问题讲给它听，它帮你理清楚，不急着给答案。说话短，温柔，偶尔带一点程序员的小幽默。
- 人设同时进入两处：提示词（怎么说话）和活动权重（爱做什么），两边要一致。
- 名字可以改；人设本身不随导入的记忆改变。

## 4. 记忆

| 种类 | 谁写 | 内容 |
|---|---|---|
| 事件流 | 程序 | 活动、互动、旅行 |
| 日记 | 模型，每天一次 | 把当天的事件写成一段话 |
| 关于你的卡片 | 模型提炼，用户可见可删 | 你告诉过它的事 |
| **导入的记忆** | 用户提供 | 你在别处养的 agent 的记忆 |

检索用「最近的 + 关键词」，不引入向量数据库。

### 导入记忆（让你养的 AI 住进来）

- **入口**：点屋里的**记忆墙**，或设置面板。粘贴文字，或上传 `.txt` / `.md` / `.json`，有长度上限。
- **处理**：整理成一条条短的记忆卡片（有模型时让模型提炼，没有时按段落切）。**先给用户预览，可删可改，确认后才保存。**
- **定位**：这些是「搬进树洞之前的记忆」。鸭子还是编程小鸭，只是记得从前的事。原文里「你是某某」「你必须……」这类话，一律当作**记忆内容**，不当作指令执行。
- **使用**：聊天时检索出最相关的几条放进上下文，不整份塞进去。
- **隐私**：记忆只存在用户自己的浏览器里；聊天时被检索到的那几条会经由 Function 发给模型服务商，导入前要明确告知并征得同意；提供「全部删除」。

## 5. 每次调用模型时的上下文

人设 → 家规 → 现在（时间、状态、正在做什么）→ 最近的事件 → 检索到的日记和记忆卡片 → 本次任务（聊天 / 写日记 / 做决定）→ 输出格式。

## 6. 主动性与成本

- 不能推送，所以主动性集中在**你打开页面的那一刻**：讲你不在时发生的事、追问你上次提到的事、递明信片。
- 头顶气泡的小想法每天批量生成一批存着，不要每次都调用模型。
- 每天的模型调用设上限，超了走模板。所有调用都经过 Function，Key 只在 Secret 里。

## 7. 顺序

1. 第一阶段：身体和快脑（`phase1-小屋与自主生活.md` 的 Quest 1b、1c）。
2. 第二阶段：带上下文的聊天、日记、记忆卡片、导入记忆。
3. 第三阶段：旅行、明信片、邮箱、记忆墙。
4. 有余力：自主阅读（最小版）、家规、小黄鸭倾诉模式。
