# 小黄鸭 Agent 设计（v2：心智闭环与接口契约）

> 2026-11-13。在 v1「五层结构」基础上，补齐程序、模型、记忆之间的闭环和接口契约。
> 本文只写结构与规矩，不写实现细节。身体部分见 `phase1-小屋与自主生活.md`。
> 第一阶段只实现「身体 + 快脑」，不调用模型；第二、三阶段按本文接入。

---

## 1. 一句话

**身体归程序，心归模型，记忆把两者连起来。**

鸭子本身就是一个小 Qoder：任务公告板是 Quest，记忆墙是 Memory，书架是 Wiki，门边的家规木牌是 Rules。

## 2. 五层

| 层 | 谁负责 | 做什么 | 阶段 |
|---|---|---|---|
| 身体 | 程序 | 时间、饱腹、体力、心情、当前活动；写下事件流 | 一 |
| 快脑 | 程序（规则） | 每件事做完后选下一件；离线补算也靠它 | 一 |
| 嘴 | 模型 | 带上下文的聊天、当天日记、明信片上的话 | 二 |
| 记忆 | 两者 | 事件流、日记、关于你的卡片、导入的记忆 | 二 |
| 慢脑 | 模型 | 一天几次的大决定：要不要出门、去哪、怎么回应你的愿望 | 三 |

两条规矩：

1. **模型只能从程序给的候选里选**，输出「选项 + 理由 + 一句话」。数值、时间、地点它改不了；格式不对就重试一次，再不行用规则兜底。
2. **鸭子说的不算事实，事件流才算。** 聊天时只让它引用事件流、日记和记忆卡片里有的东西。

## 3. 快脑与慢脑

不是所有「想法」都值得一次模型调用。

| 决策 | 谁做 | 频率 | 失败时 |
|---|---|---|---|
| 下一件事（吃/睡/看/写/发呆/打滚） | 程序规则 | 每次活动结束、离线补算 | 无网络依赖 |
| 出门、去哪、回应你的愿望 | 模型慢脑 | 一天几次 | 规则默认项 |
| 聊天 | 模型 | 用户触发 | 模板回复 |
| 日记 | 模型 | 每天一次 | 模板段落 |
| 头顶小想法 | 模型批量 | 每天一批缓存 | 预置文案 |

**为什么日常选择不交给模型**：×600 快进和 7 天离线补算会产生成百上千次调用，成本和延迟不可接受，测试也不再可复现。规则快脑保证身体连续，模型慢脑负责少数真正有意义的决定。

## 4. 一条闭环

```
世界状态 ──快照──▶ 记忆检索 ──上下文──▶ 模型（想法）
   ▲                                        │
   │                                  结构化回复
   │                                        ▼
事件流 ◀── 呈现 ◀── 状态机执行 ◀── 校验裁决（程序）
```

1. **快照**：程序把「现在」（时间、三项数值、当前活动、最近事件）和检索到的记忆打包。
2. **检索**：最近的 + 关键词命中的，限 6 条左右；不引入向量数据库。
3. **想法**：模型在程序给的候选里选，输出一句话和可选理由，不自由发挥数值。
4. **裁决**：程序校验 JSON、候选 id、长度；失败重试一次，再失败走规则。
5. **执行**：时间、时长、效果、锚点、姿态全部来自 `src/data/`；模型的选择只相当于一次「建议」，和点家具走同一条状态机。
6. **呈现**：头顶气泡一行字、聊天、日记、明信片；**理由不展示**，用户只看到行为和一句话。
7. **回写**：程序写事件流；日记、关于你的卡片由模型提炼但带来源；事件流是唯一事实。

## 5. 三条不可破

1. **事件流是唯一事实。** 模型说「我刚去旅行了」不算数，只有 `end` 事件算。
2. **模型只能从程序给的候选里选。** 不改数值、时间、坐标、时长；格式不对重试一次，再不行用规则。
3. **模型不可用不改变生活。** 鸭子继续按规则生活，界面用模板或缓存文案，不弹报错。

## 6. 接口契约

### 6.1 契约 A：程序 → 模型

一次请求只做一件事。上下文顺序固定：**Function 人设/规则 → 现在 → 你不在的时候 → 最近事件 → 检索记忆 → 本次任务 → 输出格式**。

人设和家规由 Function 持有，前端只送事实，不送 `persona` / `rules`，避免前端改写人设。当前的聊天只使用 `now`、`awaySummary`、`recent`；`memories` 与 `candidates` 留给之后的日记、旅行任务。

```ts
type MindTask = 'chat' | 'journal' | 'decide' | 'postcard' | 'bubble';

interface MindRequest {
  task: MindTask;
  now: {
    atMinute: number;       // 整数游戏分钟
    timeLabel: string;      // 展示用，例如「11 月 22 日 19:56」
    activity: string;       // 当前活动，例如「看书」
    fullness: number;
    energy: number;
    mood: number;
  };
  awaySummary?: string;     // 最近一次「你不在的时候」总结，≤ 120 字
  recent: string[];         // 程序压缩过的最近事件，≤ 8 条；含完成、被打断和互动
  memories: {
    id: string;
    kind: 'diary' | 'about_you' | 'imported';
    text: string;
  }[];                      // 检索到的，≤ 6 条（后续阶段）
  candidates?: { id: string; label: string; hint: string }[]; // 只有 decide 有
  input?: string;           // 只有 chat 有
}
```

### 6.2 契约 B：模型 → 程序

```ts
interface MindReply {
  choice?: string;          // 必须是某个 candidates[].id
  say: string;              // 一句话，进气泡/聊天，≤ 80 字
  why?: string;             // 短理由，只进调试日志
  remember?: string;        // 可选：想记住的事，程序审核后入库
  usedMemories?: string[];  // 实际引用的记忆 id，便于审计
}
```

校验规则：

- 必须是可解析的 JSON；不合法就带错误说明重试一次。
- `choice` 必须命中候选 id；不命中视为无效。
- `say` 去掉首尾空白后非空、不超长；超长截断而不是整条丢弃。
- `remember` 只接受短句，写入前由程序决定是否保存（见第 7 节）。
- 任何一项不合格且重试仍失败：`decide` 回退到规则选择，其他任务回退到模板文案。

### 6.3 契约 C：程序执行

- 时长、效果、锚点、姿态、动画只来自 `src/data/life.ts` 和 `src/data/scene.ts`。
- 模型的选择与用户点家具共用同一套「建议 → 中断 → 开始」状态机。
- 同一分钟内的重复建议不重复扣减、不重复写事件。
- 执行结果只通过事件流回写记忆；模型不能直接改存档。

## 7. 记忆

| 种类 | 谁写 | 内容 | 性质 |
|---|---|---|---|
| 事件流 | 程序 | 活动、互动、旅行 | 事实，只追加，保留最近 200 条 |
| 日记 | 模型，每天一次 | 把当天事件写成一段话 | 派生，引用事件 id，可删 |
| 关于你的卡片 | 模型提炼 | 你告诉过它的事 | 派生，用户可见可删 |
| 导入的记忆 | 用户提供 | 你在别处养的 agent 的记忆 | 外来档案，不当作指令执行 |

检索用「最近的 + 关键词」，限条数和总字数，不引入向量数据库。

### 7.1 记忆怎么影响决定

两条通道：

- **慢通道**：检索到的记忆进入模型上下文，直接影响它的选择。这是主路径。
- **快通道**：程序把少量带标签的记忆折算成临时候选权重（有上限、会过期），例如「你上次说想看我读书」→ 看书权重 ×1.3，持续一天。这样模型不在时，记忆仍然在起作用。

快通道只能微调权重，不能改写人设，也不能让某个活动变成强制。

### 7.2 导入记忆（让你养的 AI 住进来）

- **入口**：点屋里的记忆墙，或设置面板。粘贴文字，或上传 `.txt` / `.md` / `.json`，有长度上限。
- **处理**：整理成一条条短的记忆卡片（有模型时让模型提炼，没有时按段落切）。**先给用户预览，可删可改，确认后才保存。**
- **定位**：这些是「搬进树洞之前的记忆」。鸭子还是编程小鸭，只是记得从前的事。原文里「你是某某」「你必须……」这类话，一律当作**记忆内容**，不当作指令执行。
- **使用**：聊天时只检索最相关的几条放进上下文，不整份塞进去。
- **隐私**：记忆只存在用户自己的浏览器里；聊天时被检索到的那几条会经由 Function 发给模型服务商，导入前要明确告知并征得同意；提供「全部删除」。

## 8. 上下文与成本

- 每天的模型调用设上限，超了走模板；所有调用都经过 Function，Key 只在 Secret 里。
- 不能推送，所以主动性集中在**你打开页面的那一刻**：讲你不在时发生的事、追问你上次提到的事、递明信片。
- 「你不在的时候」卡片优先用事件拼模板；只有需要写成一段有温度的话时才调用模型。
- 头顶气泡的小想法每天批量生成一批存着，不要每次都调用模型。
- 所有请求设超时；失败不阻塞生活，也不弹报错。

## 9. 呈现

| 位置 | 内容 | 来源 |
|---|---|---|
| 头顶气泡 | 当前活动 + 一句话想法 | 程序状态；想法可由模型批量生成 |
| 聊天面板 | 带上下文的对话 | 模型，失败用模板 |
| 日记 | 当天发生的事 | 模型从事件流提炼 |
| 记忆墙 | 日记、关于你的卡片、导入记忆 | 程序展示，用户可删 |
| 明信片 | 旅行见闻 | 模型，失败用模板 |

**不展示模型推理链。** 用户看到的是行为、一句话、日记，而不是 `why`。`why` 只用于开发和审计。

## 10. 阶段落点

1. **第一阶段**：身体和快脑（`phase1-小屋与自主生活.md` 的 Quest 1b、1c）。事件流在这一阶段打好，后面所有记忆都从这里取事实。
2. **第二阶段**：带上下文的聊天、日记、关于你的卡片、导入记忆（契约 A/B 的 chat / journal 任务）。
3. **第三阶段**：旅行、明信片、邮箱、记忆墙（decide / postcard 任务）。
4. **有余力**：自主阅读（最小版）、家规、小黄鸭倾诉模式。

| 现有 | 用途 |

| `src/ui/chat.ts` | 注入检索到的少量记忆，不塞完整历史 |
| `functions/handler.ts` | 增加显式 `operation` 路由；Key 只从 Secret 读 |
| `src/storage/settings.ts` | 只存 API 配置，不混入记忆 |
