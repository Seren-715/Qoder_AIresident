# 第三阶段 Spec：旅行与明信片（v1）

> 11-22。基于 `main` 的 `0aa0239`（第一阶段和上下文聊天已完成）。
> 完成标志：**鸭子会自己出门旅行；回来时邮箱里多一张明信片，上半部分是目的地的画，下半部分是它讲的旅途小故事。**
> 排期：约 6～7 小时（3a 约 2.5 小时，3b 约 3 小时，3c 约 1 小时），另有美术约 1 小时（GPT 出图，Claude 处理）。

## 0. 这一版做什么、不做什么

| 这一版（比赛前） | 以后（第 7 节，先留接口） |
|---|---|
| 6 个**固定的真实地点**，每处一张手绘风格的画 | 接入真实地图 API，按真实地点取照片 |
| 明信片的画是预先准备好的素材 | 用重绘模型把照片转成游戏画风 |
| 故事：有模型时由模型写，没有时用模板 | 同左 |

固定地点不是临时方案，而是**永久兜底**：以后地图 API、重绘失败或超时，都回退到这 6 个地点。

## 1. 体验流程

1. **出门**：白天的某个时候，鸭子自己决定去旅行。屋里的鸭子消失，门口留一张字条：「去乌镇了，大概 17:40 回来」。屋外的小路上能看到背着包的鸭子（只在刚出发和快回来时出现）。
2. **旅行中**：大约 3～9 个游戏小时。点家具时，鸭子不会回应，气泡提示「它出门旅行了，还没回来」。
3. **回来**：鸭子回到屋里，接着按规则生活（多半先去吃饭）。屋外**邮箱上出现一个小红点**。
4. **看明信片**：点邮箱，弹出明信片：
   - 上半部分是目的地的画；
   - 下半部分是故事、地名和日期邮戳。
5. **收藏**：点屋里墙上那串照片，打开相册，按时间看所有收到的明信片。
6. **离线**：如果旅行发生在你不在的时候，「你不在的时候」卡片里写「还去了一趟乌镇，带回一张明信片」，卡片上加一个「去邮箱看看」按钮。

鸭子**自己决定**去哪；用户只能点屋外的路牌建议它出去走走（第 3.5 节），不能指定目的地。这是「你能影响但不能控制它」的延续。用户的「愿望」以后交给慢脑（`agent-设计.md` 第 3 节）。

## 3. 模拟（`src/sim/`，纯函数）

### 3.1 新活动 `travel`

| 项目 | 值 |
|---|---|
| 家具 | 无（鸭子不在屋里） |
| 时长 | 由目的地决定，见第 2 节 |
| 效果（整段合计） | 体力 −20，饱腹 +30（路上吃了当地小吃），自然消耗照常 |
| 心情目标 | 旅行中 85 |
| 条件 | 出发时间 08:00～12:00；体力 ≥ 60；饱腹 ≥ 60；距离上次**回来**至少 20 小时 |
| 需求分 | 可选时固定 55，性格权重 1.0 |

- 出发时间限制保证**最晚 21:00 前回来**，不会在外过夜，夜里照常睡觉。
- 冷却 20 小时：大约每天最多一次，有的日子因为体力、饱腹不够或别的活动分数更高，不会出门。
- ×600 时 1 秒等于 10 游戏分钟，一天约 2.4 分钟，评委看几分钟就能等到一次旅行。

### 3.2 选目的地

出发时用存档里的随机数选：**先去没去过的地方**，6 处都去过之后再随机，且不连续两次去同一处。时长在该目的地的范围里取。

### 3.3 旅行中不能被打断

- 强制吃饭、强制睡觉只在选下一件事时检查，旅行中不检查。
- 点家具：记一条 `interact` 事件，结果为 `rejected`，气泡「它出门旅行了，还没回来」。
- 设置里的「重新开始」仍然有效。

### 3.4 状态与事件

- `LifeActivity` 增加可选的 `destinationId`（只有 `travel` 有）。
- 事件的 `start`、`end` 也带 `destinationId`。
- `LifeState` 增加 `trips: Trip[]`，**只追加，不受事件 200 条上限影响**，最多保留 60 条：

```ts
interface Trip {
  id: string;             // = 这次旅行的 activityId
  destinationId: string;
  departedAt: number;     // 游戏分钟
  returnedAt: number;
  read: boolean;          // 明信片是否看过
}
```

- 旅行**完整结束**（`end` 事件）时追加一条 Trip。本阶段旅行不会被打断；如果以后被打断，就不生成明信片。
- 存档兼容：旧存档没有 `trips` 时按空数组读入，**不要因此重新开局**。`destinationId` 必须是已知的目的地 id，否则这条存档按损坏处理。

### 3.5 点屋外的路牌 = 建议它出去走走

自主旅行大约两天一次，评委不一定等得到，所以给一个「建议」入口，和点家具一样是建议，不是命令：

- 点屋外的路牌（约 (75, 53)）：
  - 条件满足就出发：08:00～14:00、体力 ≥ 60、饱腹 ≥ 60、当天还没出过门。
  - 时长取该目的地的范围，但**最晚 21:00 回来**，超出就截短。
  - 不满足就用气泡说明原因：「天快黑了，明天再去吧」「太累了，先歇会儿」「肚子饿，先吃饭」「今天已经出去过啦」。
- 建议出发的旅行可以忽略 20 小时冷却，但同一个游戏日最多一次。
- 每次点击记一条 `interact` 事件，结果为接受或拒绝。

### 3.6 数值已经验证过

Claude 在本地按 3.1～3.3 的数值临时改代码跑过模拟（没有提交），8 颗种子各 14 天：

| 指标 | 结果 |
|---|---|
| 旅行次数 | 5～9 次 |
| 出发时间 | 全部在 8～11 点 |
| 21:00 之后回来 | 0 次 |
| 夜里醒着 | 10%～14% |
| 饱腹 < 30 | 0%～9% |
| 写代码 | 42～51 小时，仍多于打滚 |

夜里醒着比没有旅行时（8%～12%）略高，统计测试的阈值 < 15% 仍然满足，但余量不大。如果实现后偶尔超过，可以把阈值放宽到 16%，不要为此改作息数值。

### 3.7 明信片文字不在模拟里

故事文字（模板或模型）、画都**不进入** `advance`。模拟只决定「哪天、去了哪、什么时候回来」，保证离线补算和快进可复现、不联网。

## 5. 明信片的故事

### 5.1 先用模板，后台再问模型

1. 打开一张明信片时，如果缓存里没有这张的故事，先立即显示**模板故事**：用 `hash(trip.id)` 从该目的地的 3 条模板里选一条。
2. 同时在后台请求模型（`operation: 'postcard'`）。8 秒内拿到合格结果，就替换文字，并存进缓存；否则保留模板，并把模板存进缓存。
3. 缓存只存在本地：key `ai-resident-postcards`，`{ [tripId]: { text, source: 'model' | 'template' } }`。同一张明信片之后打开永远显示同一段文字。

### 5.2 请求与校验

前端只发事实，人设和规则在 Function 里（和聊天一致）：

```json
{
  "operation": "postcard",
  "context": { "name": "Qoduck", "now": { "...": "同聊天" }, "recent": [] },
  "trip": {
    "destination": "乌镇",
    "region": "浙江嘉兴",
    "facts": ["…", "…"],
    "departedLabel": "11 月 22 日 09:20",
    "returnedLabel": "11 月 22 日 16:05",
    "hours": 6.75
  }
}
```

Function 校验：`facts` ≤ 4 条，每条 ≤ 60 字；地名 ≤ 12 字。

系统提示词规则：

- 写一张明信片背面的话，第一人称，≤ 100 字，一到三句。
- 只能写 `facts` 里的景物和事实；可以写自己的感受和一个和编程有关的小联想。
- 不写具体的票价、营业时间、天气数据、新闻或其他实时信息。
- 只输出正文，不要标题和署名。

回复校验：去掉首尾空白后非空；超过 100 字按句号截断；包含「作为 AI」「我无法」之类的话就视为不合格。

### 5.3 不在这里调用模型的地方

- 离线补算、快进：只生成 Trip，不调用模型。
- 「你不在的时候」卡片：用模板拼一句，不调用模型。

## 7. 以后：真实地图与重绘（本阶段只留接口，不实现）

```ts
interface DestinationSource {
  /** 给模拟用：返回可选目的地，必须同步、不联网 */
  candidates(): Destination[];
}
// 本阶段：FixedDestinationSource，只返回第 2 节的 6 处。
```

以后的流程：

1. **候选**：按天预取一批真实地点（地图 API 的 POI 搜索），存进本地，作为模拟可以选的候选。模拟本身仍然不联网。
2. **出发时**：后台开始准备这张明信片的画。
   - 用地点的照片，交给重绘模型转成游戏画风。
   - 重绘的风格参考图固定为 `room-exterior.webp`。
   - 结果存进 Qoder Sites 的文件存储，按地点 id 缓存。
   - 旅行要几个游戏小时，正好掩盖生成时间。
3. **兜底**：没取到照片、重绘失败或超时，都用固定目的地里最近的一处的画。
4. **要先确认的风险**：
   - 地图服务商对照片的缓存和二次加工条款，很多服务不允许这样用；
   - 重绘的成本和次数上限；
   - 生成图片的内容安全审核；
   - 离线补算期间发生的旅行，要在打开页面时补生成。

## 附录 A：目的地数据

`facts` 给模型用，只写稳定的常识，不写票价、时间、天气。`templates` 是兜底故事，第一人称，≤ 100 字，`{name}` 不需要，署名由界面加。

### xihu 西湖·断桥（杭州）

- facts
  - 断桥在白堤的一头，「断桥残雪」是西湖十景之一。
  - 湖边种着很多柳树，湖上有手划的小船。
  - 远处的山上能看到保俶塔。
- templates
  1. 我在断桥上站了好久，湖面平得像一块没有 diff 的屏幕。回去的路上一直在想，要是代码也能这么安静就好了。
  2. 柳树垂到水面上，小船慢慢划过去。我数了数桥上的台阶，又数了一遍，确认没有 off-by-one。
  3. 远处山上有座塔，我把它当成今天的书签。下次来，想从塔上往下看看这片湖。

### yunqi 云栖小镇（杭州西湖区）

- facts
  - 云栖小镇在杭州西南的山谷里，周围是竹林和茶山。
  - 每年的云栖大会在这里举办，聚集了很多做云计算和 AI 的人。
  - 小镇里有一条安静的溪流和竹林小路。
- templates
  1. 我去了云栖小镇，听说很多会写代码的人每年都会来这里。我在竹林边坐了一会儿，感觉自己也算来过大会了。
  2. 山谷里很安静，只有溪水声。我在想，云到底是什么呢？大概就是你看不见、但一直在帮你干活的东西吧。
  3. 竹子长得又直又高，一节一节的，像排好的函数调用栈。我在这里写了半个 TODO，剩下的回家补。

### wuzhen 乌镇（浙江嘉兴）

- facts
  - 乌镇是江南水乡古镇，河道穿过小镇，两边是白墙黑瓦的老房子。
  - 河上有乌篷船和很多石桥。
  - 世界互联网大会在乌镇举办。
- templates
  1. 乌镇的河弯弯绕绕，像一段没有注释的老代码，但走着走着就懂了。我坐了一会儿乌篷船，船夫划得比我写代码还稳。
  2. 白墙黑瓦，石桥一座连着一座。听说互联网大会在这里开，我在桥上替你连了一下 Wi-Fi，信号很好。
  3. 傍晚河面上有灯，倒影晃来晃去。我在想，老房子能用几百年，是因为一直有人在维护吧。

### qiandaohu 千岛湖（杭州淳安）

- facts
  - 千岛湖是一片很大的湖，湖里有一千多座小岛。
  - 湖水很清，坐渡船在岛之间穿行。
  - 湖边是连绵的青山。
- templates
  1. 湖里有好多好多小岛，我数到第 37 个就放弃了，决定把它当成一个很长的数组。
  2. 坐渡船从一座岛到另一座岛，像在一个个模块之间跳转。湖水清得能看到底，我很喜欢这种没有隐藏 bug 的感觉。
  3. 我在一座小岛上发了会儿呆，四面都是水。原来离开电脑屏幕，世界这么宽。

### moganshan 莫干山（浙江湖州）

- facts
  - 莫干山有大片竹海，夏天很凉快，是有名的避暑地。
  - 山上有石阶小路和很多老房子。
  - 山间有溪流和小瀑布。
- templates
  1. 竹海被风吹得沙沙响，我爬了好多级石阶，体力条掉了一大截，但心情条涨满了。
  2. 山上有很多老房子，藏在竹子后面。我在溪边洗了洗脚丫，突然想通了昨天卡住的那个 bug。
  3. 这里好凉快。我在一块石头上躺了一会儿，听瀑布的声音，像一个永远不会结束的 while 循环，但很舒服。

### huangshan 黄山（安徽）

- facts
  - 黄山以奇松、怪石、云海出名。
  - 山峰很高，常常能看到云海在山间流动。
  - 山上有长长的石阶路。
- templates
  1. 我爬上了黄山，脚下全是云，像站在一大片棉花糖上。回来的路上我一直在想，云服务是不是就住在这里。
  2. 有一棵松树从石缝里长出来，歪着身子迎客。我觉得它很像一个历史悠久但依然在线的老项目。
  3. 石阶好长好长，我走了好久才到顶。看到云海那一刻，觉得所有的 commit 都值得。
