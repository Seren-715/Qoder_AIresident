## 1. 设计

### 1.1 时间

- 游戏时间 = 现实时间（1:1）：晚上睡觉，白天活动。
- 内部单位：**整数分钟**，从 `2026-01-01 00:00（北京时间）` 起算。模拟逻辑里不直接用 `Date` 做运算。
- **快进**：×1 / ×60 / ×600（现实 1 秒 = 游戏 1 秒 / 1 分钟 / 10 分钟）。快进后游戏时间可以领先现实时间。

### 1.2 状态

三项数值，0～100，**越高越好**：

| 状态 | 含义 | 自然变化（每小时） |
|---|---|---|
| 饱腹 `fullness` | 饿不饿 | −6 |
| 体力 `energy` | 累不累 | −4（睡觉时不扣） |
| 心情 `mood` | 开不开心 | 饱腹或体力低于 30 时 −3，否则 0 |

另外记录当前活动（含 `activityId`、开始分钟、计划结束分钟）。鸭子出现在哪由当前活动决定，不单独存位置。

### 1.3 活动（对应现有家具和姿态）

| 活动 | 家具（`FURNITURE`） | 姿态 | 时长（分钟） | 效果（整段合计） | 条件 |
|---|---|---|---|---|---|
| `sleep` 睡觉 | `bed` | `sleep` | 120～480 | 体力回到 100，心情 +5 | 体力 < 40，或夜里 23:00～07:00 |
| `eat` 吃饭 | `bowl` | `eat` | 20～40 | 饱腹 +50，心情 +5 | 饱腹 < 70 |
| `read` 看书 | `bookshelf` | `read` | 40～90 | 心情 +10，体力 −5 | 体力 ≥ 20 |
| `code` 写代码 | `desk` | `back` | 40～120 | 心情 +8，体力 −10 | 体力 ≥ 30 |
| `gaze` 发呆 | `window` | `sit` | 15～40 | 心情 +6 | 无 |
| `play` 打滚 | `rug` | `play` | 15～30 | 心情 +12，体力 −8，饱腹 −5 | 体力 ≥ 25 |
| `away` 不在家 | — | — | — | — | **本阶段只保留这个状态，不会被选中**；第三阶段旅行用 |

- 效果按时长**均匀生效**；被打断时按已经过的比例结算。
- 锚点、姿态、气泡继续用 `src/data/scene.ts` 里现有的，不要另建一套。
- 可选（有余力再做）：`swim` 泡水。贴图 `duck-swim.png` 已有，需要给屋内水池加一个锚点，建议 `(10.2, 88.2)`。

### 1.4 性格：默认是 Qoder 的编程小鸭

不做「开局选性格」。默认只有一套偏好权重，写在 `src/data/` 里，以后导入记忆或家规时可以调整：

| 活动 | `eat` | `read` | `code` | `gaze` | `play` | `sleep` |
|---|---|---|---|---|---|---|
| 编程小鸭 | ×1.0 | ×1.3 | ×1.6 | ×1.0 | ×0.9 | ×0.9 |

名字默认「Qoduck」，可以在设置面板里改。

### 1.5 怎么选下一件事

一件事做完时选下一件：

1. 去掉不满足条件的活动。
2. 打分：`分数 = 需求分 × 性格权重 × 随机因子(0.8～1.2)`。
   - 吃饭的需求分 = `100 − 饱腹`；睡觉 = `100 − 体力`（夜里再 +40）；其余 = `100 − 心情 + 20`。
3. 选分数最高的；时长在范围内用同一个随机数发生器取。
4. **饱腹 < 20 强制吃饭；体力 < 10 强制睡觉。**
5. 不连续两次选同一种娱乐活动（看书、写代码、发呆、打滚）。

数值是起点，集中放在 `src/data/`，做完后按手感调。

### 1.6 点家具 = 向鸭子提建议

现在点家具是直接摆姿态。有了自主生活后改成「建议」：

- 条件满足：鸭子**中断**当前活动（按比例结算），去做被点的那件事，时长取该活动范围的下限到中值。
- 条件不满足：不去，气泡说明原因（例如体力太低时点书桌 →「太困了，先睡一会儿」）。
- 睡觉时被点：体力 ≥ 60 时会被叫醒，否则气泡「呼……」。
- 每次点击记一条「互动」事件。

这是「你能影响但不能控制它」的最小实现。

### 1.7 事件

每个活动开始、结束（或被打断）各记一条事件，只保留最近 200 条：

```
{ id, type: 'start' | 'end' | 'interrupt' | 'interact',
  activityId, activity, atMinute, startedAtMinute?, endedAtMinute?, delta? }
```

- `activityId` 稳定且唯一（例如由存档 ID + 序号生成）。
- **只有 `end` 才表示活动完整做完。** 阅读系统（`docs/spec/reading-system-architecture.md` 的 `ReadingIntent`）、日记、旅行都从这条事件流取事实。

### 1.8 核心函数

```
advance(state, toMinute, rng) → { state, events }
```

- 纯函数：不访问 DOM、`localStorage`、网络；随机数用可设种子的发生器，种子存在状态里。
- 把世界从当前分钟推进到 `toMinute`，中间跨过多少个活动就处理多少个。
- 实时运行、快进、离线补算**都只调用这一个函数**，区别只是 `toMinute` 怎么来。

## Quest 1b：状态与自主行为（约 3 小时）

**做什么**

- `src/sim/`：状态结构、可设种子的随机数、1.2 的自然变化、1.3 的活动效果、1.5 的选择、1.7 的事件、1.8 的 `advance`。
- 数值表放 `src/data/life.ts`（或类似名字）。
- 接入场景：页面每秒调用一次 `advance`，鸭子按结果出现在对应家具、换姿态、换气泡。只在屋内显示鸭子，和现在一致。
- 点家具改为 1.6 的「建议」。
- 界面：三项状态的小进度条和当前游戏时间。位置避开右上角的设置按钮，375px 宽时不溢出。
- 本 Quest 先不存档：刷新后从一个固定初始状态开始（饱腹 70、体力 80、心情 70，当前现实时间）。

**验收**

- [ ] `tests/` 新增 sim 的单元测试：饱腹 < 20 一定去吃饭；夜里优先睡觉；同一种子结果完全一致；推进 7 天后三项数值始终在 0～100；被打断的活动按比例结算；事件里 `end` 与 `interrupt` 区分正确。
- [ ] 统计测试：推进 7 天，写代码的次数明显多于打滚（体现编程小鸭的偏好），每天都有睡觉和吃饭。
- [ ] 浏览器里不点任何东西，鸭子会自己换地方、换气泡；点家具时按 1.6 响应。
- [ ] 现有的聊天、设置、物件动效、水面、内外景切换不受影响；`npm run build`、`npm test` 通过。

**交给 Qoder 的话**

## Quest 1c：存档、离线补算、快进（约 2.5 小时）

**做什么**

- **存档**：`src/storage/life.ts`，独立的 `localStorage` key（不要和 `ai-resident-settings` 混在一起），带版本号。内容：状态、随机种子、事件、名字、最后更新的分钟。每 10 秒和页面隐藏 / 关闭时各存一次。版本不认识或数据损坏时重新开局，不白屏。
- **离线补算**：打开页面时用 `advance` 从存档时间推进到现在。离开超过 7 天只补最近 7 天。
- **「你不在的时候」卡片**：补算跨度超过 10 分钟时显示，用事件生成几句话，例如「你不在的 3 小时里，小黄鸭睡了一觉，吃了 1 次饭，还写了一会儿代码。现在它在窗边发呆。」文字用模板拼，不调用模型。
- **快进**：×1 / ×60 / ×600 切换，不挡住场景和设置按钮。
- **重新开始**：放进设置面板，需要二次确认。
- 多标签页同时打开的情况本阶段不处理（后写入的覆盖先写入的即可）。

**验收**

- [ ] 关闭页面，手动把存档里的时间改早 3 小时再打开：状态合理变化，弹出总结卡片，内容与事件一致。
- [ ] 存档损坏、版本不符时自动重新开局。
- [ ] ×600 时，几分钟内能看到鸭子过完一整天（包括夜里睡觉）。
- [ ] 补算 7 天用时不到 1 秒（写成测试）。
- [ ] `npm run build`、`npm test` 通过；375px 下卡片、状态条、快进按钮都可用。

**交给 Qoder 的话**

> 请阅读 `.qoder/rules/project.md` 和 `docs/spec/phase1-小屋与自主生活.md`（v2），完成「Quest 1c：存档、离线补算、快进」。新增 `src/storage/life.ts`（独立 key、带版本号）；打开页面时用 `advance` 补算离线时间（最多 7 天），超过 10 分钟显示「你不在的时候」卡片；加上 ×1 / ×60 / ×600 快进和设置面板里带二次确认的「重新开始」。为存档和补算写测试。不调用大模型。完成后运行构建和测试并报告结果，经我确认后再发布到 Qoder Sites（保持私有）。
