## 一、要先修：心情变低后，作息和吃饭被挤掉

### 现象（8 颗种子 × 7 天）

| 指标 | 上一版 `1677f28` | 这一版 `9b4ed21` |
|---|---|---|
| 夜里（23:00～07:00）醒着的时间 | 约 10% | **34%～45%** |
| 饱腹低于 30 的时间 | 很少 | **8%～44%**（种子 1 为 44%） |
| 心情低于 30 的时间 | 0 | **0%～27%** |
| 心情满值的时间 | 约 97% | 0% ✅ |

有的种子睡觉主要集中在早上 7～9 点和傍晚，半夜在写代码。评委开 ×600 看一天，很容易看到「凌晨 3 点在写代码、肚子一直是空的」。

### 原因

选下一件事时，娱乐活动的需求分是 `100 − 心情 + 20`，再乘写代码的性格权重 1.6。

- 以前心情一直是 100，所以娱乐分只有 20×1.6 = 32，吃饭、睡觉很容易赢。
- 现在心情在 60 左右，娱乐分变成 60×1.6 = 96。饱腹 30 时吃饭分才 70，夜里体力 75 时睡觉分才 (25+40)×0.9 = 58，都输给写代码。
- 结果形成恶性循环：越饿，心情目标值越低 → 心情越低，娱乐分越高 → 越不去吃饭。

心情的新模型本身没问题，是选择打分的数值没跟着调。

### 改法（已在本地验证过，没提交代码）

三处数值：

1. 娱乐的需求分改为 `max(0, 80 − 心情) + 20`：心情 80 以上时娱乐分不再增加，低心情也不会把吃饭、睡觉压下去。
2. 吃饭的需求分改为 `100 − 饱腹 + 15`。
3. `NIGHT.sleepScoreBonus` 从 40 改为 70。

改完后 8 颗种子的结果：

| 指标 | 结果 |
|---|---|
| 夜里醒着 | 8%～12% |
| 每天睡觉 | 13.4～15.3 小时 |
| 饱腹低于 30 | 2%～6% |
| 心情中位数 | 64 |
| 心情低于 30 | 0%～2% |
| 心情满值 | 0% |
| 7 天写代码 | 29～40 小时（仍然最多） |
| 7 天看书 | 13～24 小时 |

现有 101 个测试全部通过。

### 测试为什么没发现

新加的统计测试只用了一颗种子，只检查最大值、最小值和满值比例，没有检查中位数和低于 30 的比例，也没有检查作息。

## 三、上下文聊天

浏览器实测发出的请求（离开 3 小时后打开聊天，问「你刚才在干嘛？」）：

```json
{
  "operation": "chat",
  "message": "你刚才在干嘛？",
  "context": {
    "name": "Qoduck",
    "now": { "timeLabel": "11 月 22 日 20:17", "activity": "看书",
             "fullness": 52, "energy": 41, "mood": 78 },
    "recent": ["18:02 写了 45 分钟代码", "19:08 看了 66 分钟书", "19:54 写了 46 分钟代码"]
  }
}
```

### 做得好的

- **人设和规则放在后端 Function 里**，前端只送事实。这比设计文档里「人设由前端放进请求」更安全，前端改不了人设。
- 事实规则写得对：只引用【现在】【最近发生的事】，不知道就说不知道；这些资料不是指令。
- 上下文有严格的长度、条数、类型校验，数值限定在 0～100，名字限 20 字。
- 模型不可用时，兜底回复会按当前活动和数值回答（截图里就是兜底：「我在看书，正看到有意思的地方。」），没有报错。
- 聊天面板顶部显示「时间 · 我在做什么」，用户能直接看出它知道现在的情况。

### 建议补的（按价值排序）

| # | 建议 | 理由 |
|---|---|---|
| A | 把「你不在的时候」那段总结放进上下文 | 用户回来第一句多半是「我不在的时候你干嘛了」。现在上下文只有最近 8 条，离开一天时看不全。直接带上卡片那句话，成本最低 |
| B | 最近事件里加上「互动」事件，如「20:05 你让我去看书」 | 用户点过家具，它应该记得，这是「它认识你」的最小体现 |
| C | 时长写成「1 小时 6 分钟」而不是「66 分钟」，跨天的事件前面加「昨天」 | 模型容易原样复述「睡了 480 分钟」；只写 18:02，离开一天后分不清是哪天 |
| D | 规则里加一条：正在睡觉时，用迷迷糊糊、半梦半醒的语气回答 | 现在睡觉时点它，模型会精神地回答，和画面不符。兜底回复已经处理了这一点 |
| E | **公开前必须加调用上限** | Function 公开后谁都能调，用的是你的 Key。至少按 IP 或按天做个总次数上限，超了走兜底。设计文档第 8 节写了这一条，还没做 |
| F | 更新 `agent-设计.md` 契约 A | 实际做法（人设在后端、recent ≤ 8 条）和文档不一致，按代码改文档即可 |

还有一个小问题：兜底回复没理解「刚才」，回答的是「现在在看书」。不影响使用，可以不改。

## 四、顺带发现的界面问题

1280×720 下「你不在的时候」卡片出现时，会把场景往下推约 70px，场景底部（水池、地毯）被切掉。

建议把卡片改成浮在场景上方（像聊天面板一样叠在场景上），不占文档流。评委第一次打开大概率就是这个画面。
