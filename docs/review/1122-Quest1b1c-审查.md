## 需要修

### 1. 用过快进之后，离线补算失效，昼夜也错开了

**复现**：×600 看 5 分钟（游戏时间领先现实约 50 小时）→ 关掉页面 → 3 小时后回来。

**结果**：补算 0 分钟，不显示卡片，这 3 小时鸭子什么都没做。之后要等现实时间追上那 50 小时，离线补算才恢复。鸭子的白天黑夜也一直和现实错开。

**原因**：存档只记了游戏分钟。回来时用「现实时间」去补算，而存档时间在未来，`catchUpLife` 直接不动。

**改法**：存档里多存一个「领先量」`aheadMinutes = 游戏分钟 − 现实分钟`。打开页面时补算到 `现实分钟 + aheadMinutes`，时钟也从这里接着走。这样快进过的存档，离线照样会推进。

（评委一定会点快进，这个问题演示时容易撞上。）

### 2. 心情几乎一直是满的

**数据**：模拟 3 颗种子各 7 天，心情最低 70，**约 97% 的时间是 100**，从来没有低于 70。心情条在界面上基本不动，「需求分」里的心情也起不到作用。

**原因**：这是我写 Spec 时给的数值有问题，不是 Qoder 实现错了。心情只在饿或累时才下降，而每次娱乐活动都加 6～12 点，很快就顶满。

**试过的简单调法**：给心情加一个固定的每小时下降，或者再缩小娱乐的加成，结果都不稳定：要么还是顶满，要么掉到 0 回不来，不同种子差别很大。说明需要改一下心情的计算方式，而不只是调数字。

**建议的改法**：心情改成「向一个目标值慢慢靠拢」。

- 目标值 = 60，饿（饱腹 < 30）−20，累（体力 < 30）−15，正在做娱乐活动时 +25，刚吃饱（饱腹 > 80）+5。
- 每分钟按差距的一小部分靠拢（例如每小时靠拢 25%），这样心情会在一个范围里起伏，不会卡在两端。
- 加一个统计测试：多颗种子推进 7 天，心情的中位数在 50～80 之间，满值（≥ 99）的时间少于 10%，低于 30 的时间少于 10%。
