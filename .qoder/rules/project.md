# 项目规则：AI Resident · 小黄鸭的家

> 本文件是给 Qoder 的项目级规则，每个任务都必须遵守。
> 需求总纲见 `docs/00-计划与需求草案.md`，分阶段需求见 `docs/spec/`。

## 1. 项目是什么

一个网页小游戏：小黄鸭在自己的 2D 小屋里自主生活（睡觉、吃饭、看书、发呆……），偶尔出门旅行寄回明信片；用户可以看它、喂它、摸它、跟它聊天。
开发者一个人、时间很少，**简单、能跑、不出错**比功能多更重要。

## 2. 技术栈

- 前端：TypeScript + Vite。以仓库现有结构为准，不要另起框架。
- 后端：Qoder Sites 的 Function；密钥只放 Qoder Sites 的 Secret。
- 测试：Vitest。
- 不要引入游戏引擎或大型 UI 库。新增任何依赖前，先说明理由。

## 3. 目录约定

```
src/
  sim/       纯逻辑：时间、状态、行为选择、离线补算。不得访问 DOM、localStorage、网络。
  ui/        界面：小屋场景、鸭子、面板、交互。
  storage/   存档读写（localStorage）。
  data/      静态数据：家具、活动、性格、旅行目的地。
  ai/        调用后端 Function 的客户端与兜底文案（第二阶段起）。
functions/   Qoder Sites 后端函数（第二阶段起），按 Qoder Sites 的实际约定放置。
tests/       单元测试，主要覆盖 src/sim。
docs/        文档、Spec、Qoder 使用日志。
```

## 4. 必须遵守

1. **密钥绝不进前端代码和仓库**。模型调用一律经过后端 Function，Key 从 Secret 读取。
2. **任何对外调用都要有兜底**：超时、报错、额度用完时，鸭子照常生活，界面用模板文案，不弹报错。
3. **模拟逻辑是纯函数**：`src/sim` 只接收状态和时间、返回新状态和事件；随机数用可设种子的 RNG，保证测试可复现。
4. **时间用整数分钟**（从固定纪元起算），不要在模拟逻辑里直接用 `Date` 对象做运算。
5. **数值由程序算**：饥饿、体力、心情等全部由程序计算；大模型只负责「说话、写日记、写明信片」，以及在程序给出的候选里做选择。
6. **手机优先**：界面在 375px 宽的手机屏幕上必须完整可用，再适配桌面。
7. **界面文字用简体中文**，语气温柔、轻松。
8. **小步提交**：每完成一个可运行的小目标就停下来，保证 `npm run build` 和 `npm test` 通过。
9. 不要修改 `docs/00-计划与需求草案.md`；需求有疑问时先提出来，不要自行改需求。

## 5. 完成任务后

1. 运行 `npm run build` 和 `npm test`，并报告结果。
2. 在 `docs/qoder-log.md` 的「每日记录」表格末尾追加一行**草稿**：日期、任务、结果。「我改了什么」和「截图」两栏留空，由开发者本人填写。
